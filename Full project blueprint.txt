# Full project blueprint

## Project title

**Bilingual LLM Annotation Assistant**

## Goal

Build a **French-English annotation workflow system** that uses an LLM to:

-   classify text
    
-   label sentiment / issue type / urgency
    
-   generate a localized summary
    
-   return structured JSON
    
-   route uncertain cases to human review
    
-   evaluate accuracy and consistency across English and French
    

This project demonstrates:

-   prompt engineering
    
-   Python
    
-   JSON / structured outputs
    
-   multilingual localization
    
-   evaluation metrics
    
-   human-in-the-loop workflow design
    
-   API integration
    
-   automation pipelines
    
-   deployment readiness
    

----------

# 1) Project scope

## Core use case

A company receives customer feedback or support messages in English and French. The system should:

1.  ingest the text
    
2.  detect language
    
3.  classify the issue
    
4.  score sentiment / urgency
    
5.  generate a normalized English summary or bilingual summary
    
6.  return structured labels in JSON
    
7.  flag low-confidence or culturally ambiguous cases for human review
    
8.  store results for auditing and analysis
    

## Example labels

-   **issue_type**: billing, shipping, product quality, account access, refund, technical issue, general inquiry
    
-   **sentiment**: positive, neutral, negative
    
-   **urgency**: low, medium, high
    
-   **needs_human_review**: true/false
    
-   **review_reason**: ambiguity, mixed language, policy-sensitive, low confidence, cultural nuance risk

# 4) Main features

## A. Data ingestion

-   upload CSV or JSON file
    
-   accept fields like:
    
    -   id
        
    -   text
        
    -   language
        
    -   gold_label optional
        
-   validate schema before processing
    

## B. Preprocessing

-   trim whitespace
    
-   remove malformed records
    
-   normalize punctuation
    
-   detect missing language tags
    
-   optionally detect language automatically
    

## C. Prompt-based annotation

For each record:

-   classify issue type
    
-   infer sentiment
    
-   infer urgency
    
-   create short summary
    
-   determine if human review is required
    

## D. Structured JSON output

Force the LLM to produce a strict schema like:

```json
{
  "language": "fr",
  "issue_type": "billing",
  "sentiment": "negative",
  "urgency": "medium",
  "summary_en": "Customer reports being charged twice for a subscription.",
  "summary_localized": "Le client signale un double prélèvement pour un abonnement.",
  "needs_human_review": false,
  "review_reason": null
}

```

## E. Human review queue

Route examples for review if:

-   JSON is invalid
    
-   confidence proxy is low
    
-   output contains unsupported label
    
-   message includes mixed English/French
    
-   content appears culturally nuanced or ambiguous
    

## F. Evaluation dashboard

Track:

-   accuracy against gold labels
    
-   F1 for issue type
    
-   sentiment accuracy
    
-   per-language performance
    
-   review escalation rate
    
-   JSON validity rate
    
-   auto-accept vs human-review ratio
    

## G. Documentation / governance

Create:

-   prompt guidelines
    
-   reviewer instructions
    
-   acceptance criteria
    
-   failure mode log
    
-   bias / localization notes

# 6) Core prompt design

## Prompt 1: annotation

The LLM receives:

-   text
    
-   language
    
-   allowed labels
    
-   localization instructions
    
-   output schema
    

It returns:

-   issue_type
    
-   sentiment
    
-   urgency
    
-   summary_en
    
-   summary_localized
    
-   needs_human_review
    
-   review_reason
    

## Prompt 2: review escalation

Use a second prompt or rule layer to check:

-   ambiguity
    
-   poor translation quality
    
-   cultural sensitivity
    
-   unsupported category
    
-   inconsistent reasoning
    

## Prompt versioning

Keep prompt versions like:

-   v1: basic classifier
    
-   v2: better JSON formatting
    
-   v3: stronger French handling
    
-   v4: more cautious escalation rules
    

This helps show structured prompt iteration.

# 7) Data plan

## Option A: easiest and best for portfolio

Use:

-   **Amazon Reviews Multi** for English/French reviews ([Kaggle](https://www.kaggle.com/datasets/mexwell/amazon-reviews-multi?utm_source=chatgpt.com "️ Amazon Reviews Multi"))
    
-   **MASSIVE** for multilingual intent labels including English and French ([Hugging Face](https://huggingface.co/datasets/qanastek/MASSIVE?utm_source=chatgpt.com "qanastek/MASSIVE · Datasets at Hugging Face"))
    
-   your own **synthetic support ticket dataset**
    

## Suggested split

-   1,000 English examples
    
-   1,000 French examples
    
-   200 manually curated bilingual support tickets
    
-   100 intentionally ambiguous examples for review routing tests
    

## Why synthetic tickets help

They let you showcase:

-   localization
    
-   human review
    
-   acceptance criteria
    
-   business-style workflow design
    

That looks closer to the actual Innodata work than only using benchmark corpora.

# 8) Evaluation plan

## Metrics to track

-   **classification accuracy**
    
-   **macro F1**
    
-   **sentiment accuracy**
    
-   **JSON validity rate**
    
-   **review escalation rate**
    
-   **false auto-accept rate**
    
-   **per-language performance**
    
-   **prompt version comparison**
    

## Bias / reliability checks

At minimum:

-   compare English vs French label accuracy
    
-   compare auto-review rates by language
    
-   inspect whether French examples are escalated more often than English
    
-   review failure cases with idioms / region-specific phrasing
    

## Acceptance criteria example

-   issue type F1 ≥ 0.80
    
-   sentiment accuracy ≥ 0.85
    
-   JSON validity ≥ 98%
    
-   low-confidence routing catches ≥ 75% of major errors
    
-   English/French performance gap ≤ 10 percentage points
